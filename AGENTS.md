# AGENTS.md

This file provides guidance to AI agents when working with code in this repository.

## Project Overview

Nexus is a static web app that draws a Drupal site's content model from its exported configuration, entirely in the browser. There's no backend and no build step: `index.html` loads the app's own ES modules and stylesheet from `src/` plus vendored libraries from `assets/vendor/`, and GitHub Pages serves the files as they are at https://nexus.drevops.com.

The project was created from the Scaffold template, which supplies the CI workflows, the linting and test tooling, and the Renovate configuration.

## Application Architecture

- **Entry point:** `index.html` declares an import map for Preact, Preact hooks and htm, loads the classic vendor scripts (Cytoscape, Dagre, cytoscape-dagre, cytoscape-svg, js-yaml) and the Shoelace autoloader, then starts `src/app.js`.
- **Model builder (pure, no DOM):** `src/parser.js` turns parsed config YAML into a `ContentModel` from `src/model.js`; `src/base-fields.js` adds curated system fields and `src/annotations.js` applies the optional `annotations.yml` overlay.
- **Shared definitions (pure):** `src/entity-types.js` lists the built-in entity types in diagram order, each with its label, default color, default symbol and the base name of bundles created on the canvas, and `formatCount()` words a count of each type's bundles. `src/annotations.js` lists the annotation kinds and the file names an overlay can have, `src/export-formats.js` lists the export formats in menu order, each with its label, icon and title, `src/names.js` converts between machine names, labels and file names, and `src/model.js` holds the default title, the field types the builder offers, the reference field types, the highest limited cardinality and the graph id helpers. Import them from there instead of keeping a local copy, so the copies can't drift apart.
- **Documents:** `src/document.js` converts between the live graph and a saved `.nexus.json` document, and its docblock holds the schema of the saved format.
- **Reference elements:** `src/references.js` derives the render-only elements that draw each reference - a proxy beside the field, the proxy edge joining them and the overview's collapsed edge - from the ref edges of a live graph. `syncReferenceElements()` reconciles them with the graph and keeps a renamed reference's proxy in place. `render.js` runs it at render time and through the controller's `syncReferences()`, which `builder.js` and `inspector.js` call after each edit the elements depend on.
- **Node text:** a Cytoscape label takes 1 style, so `src/render.js` draws each entity's type and each node's machine name in an HTML caption layer: the type on a blank last line reserved inside the entity box, the machine name below the node. `src/label-fit.js` (pure, no DOM) wraps a label the way Cytoscape does and works out how wide a box must be for every line to stay inside its shape, and where the label sits in it. `SHAPE_OUTLINES` holds the outline of each shape with corners off its bounding box. The diamond and pentagon scale with the box, while the tag, hexagon, octagon and rhomboid keep the ends they have in a square box at the same size in a wider one. Cytoscape stretches its own outline of those 4 with the width, so `render.js` draws them as a `polygon` from `polygonPoints()`. `fitWidth()` finds the narrowest box whose shape leaves every line its inset and padding, so text can run into a tag's point, and `labelX()` centres the label in the room left. A pentagon's label sits on its centroid, below the box centre, from `labelDrop()`. A proxy wraps its name over several lines like its entity, at `PROXY_BOX.textMaxWidth`, and is fitted into its shape the same way. `render.js` works each entity's and proxy's box out once in `nodeBox()`, moves the label with `text-margin-x` and `text-margin-y`, and places the type caption from the same margins, so the 2 move together. Each node's `bounds-expansion` covers its machine name, so layouts, Fit and proxy placement leave room for it.
- **History:** `src/history.js` (pure) snapshots the model elements and node positions of a graph, stores each edit as the change between 2 snapshots and applies either side of a change to undo or redo it. Its `History` class holds the versions of 1 diagram, joins edits recorded with the same coalesce key and jumps to any version in 1 apply. `src/undo.js` owns the open diagram's history and wires the Undo and Redo buttons and the History panel's jumps. `builder.js`, `inspector.js`, `render.js` and `app.js` record each finished user action with `checkpoint()`, display toggles that re-run the layout go through `untracked()`, and `app.js` starts a new history for every diagram it draws.
- **Layouts:** the toolbar's layout button is a split button like the Export button. `render.js` fills its menu from `LAYOUTS` and re-runs the picked layout when the main button is pressed. The pick lasts for the open diagram only: `buildController()` starts each diagram from the new diagram settings, which `src/diagram-defaults.js` (pure) defines and reads back from the `newDiagrams` key of the `nexusSettings` localStorage entry. They set the layout, the Fields, Proxies and Machine names switches and the mode `app.js` passes to `attachBuilder()`, and the Settings panel's **New diagrams** section edits them through the controller's `setDiagramDefault()`. A default of Edit mode starts the diagram with Fields on, since entering Edit turns them on and would re-run the layout. A saved document keeps its positions through `applyLayout()` and takes the other settings like any new diagram. A pick from the menu runs the layout through `untracked()`, like the display toggles, while the main button and Tidy each record a `checkpoint()`. LR and TB run Dagre over the whole graph. Columns, the default, runs Dagre on each island of connected elements on its own, sorts the islands by entity type order and label, and places them with `packColumns()` from `src/packing.js`, a pure module that stacks boxes in columns shaped like the canvas. The Tidy button runs Dagre on each island again and lines the islands up with `tidyColumns()` from the same module, in columns taken from where they already are, and leaves the view alone. Dagre orders an entity's fields as it likes, so `keepFieldOrder()` in `render.js` moves each field, with its proxies, back into the order the fields had before the Tidy, with `keepOrder()` from the same module: top to bottom in LR and Columns, left to right in TB. When the Inspector's screen or the node focused in View mode belongs to an entity, `tidyTarget()` returns it, Tidy works on that entity, its fields and their proxies alone, and the Tidy button's title names it. `builder.js` places a node created from a form, which has no drop position, at the nearest spot in view that clears every visible node, found with `clearSpot()` from the same module.
- **Mouse buttons:** Cytoscape zooms on the wheel only while user panning is on, so `holdPanning()` in `src/builder.js` turns it off for the length of each left-button press instead, from a capture-phase `mousedown` on the canvas. `updateInteraction()` allows grabbing, selecting and box selection only in Edit mode outside Connect, so the left button selects and moves nodes there and does nothing on the canvas elsewhere. A right-drag pans in every mode: `builder.js` follows the pointer's client coordinates on Cytoscape's `cxtdrag` events, between `cxttapstart` and `cxttapend`. Cytoscape fires no `cxttap` once the pointer has passed its tap threshold, so only a right-click without a drag isolates an entity with its fields and proxies. Grabbing a selected node makes Cytoscape drag the whole selection. While an isolation holds in Edit mode, `dragGroup()` moves the whole group when any member is dragged, following only the node under the pointer (`grabon`), and a faded node can't be grabbed. Each drag records 1 `checkpoint()` on `dragfreeon`. A double-click on a node in View mode switches to Edit mode with the node selected. The first click focuses the node and animates the view, so the double-click opens the node the first click hit, whatever the second click lands on.
- **Bulk fields:** the entity inspector's **Bulk** button opens `BulkFieldsForm` in `src/inspector.js`, a text box taking 1 field per line. `src/bulk-fields.js` (pure, no DOM) parses the lines into field definitions, or the reason a line can't be used, and its docblock describes the line format. `formatFieldLine()` writes a definition back as a line, which the form's **Copy from** select uses to fill the box from another entity. The builder's `createFields()` adds the definitions in a column beside the entity and records 1 `checkpoint()`.
- **Panels:** `src/ui.js` draws each panel with a grip handle before its title and a pin that is tilted while the panel floats and upright in the accent colour while it's docked. Dragging the header of a docked panel undocks it on the first move; dragging the grip runs `startDockDrag()`, which moves the panel within its rail or to the other one through `dockPanel()` in `src/store.js` and never undocks it. Each panel's `order` in the store places it in its rail, `dockedPanels()` lists a side's open panels in that order, and the order is saved with the rest of the layout. A floating panel dropped on a rail lands at the pointer's place among the docked panels, while the pin button keeps the order it has. `dockStyle()` keeps each docked panel at most as tall as its content: the Inspector takes its content height up to the rail's, a panel resized by its bottom edge keeps that height as a maximum, and the rest share the free space equally. `startVResize()` passes the smaller of the content and rail heights to `setPanelHeight()` as the maximum.
- **Hidden fields:** the Fields table's eye button calls the controller's `setFieldHidden()` in `src/render.js`, which sets `hidden: true` on the field node or removes the key, and records a `checkpoint()`. The key is model data, so the history and the saved document carry it, while the entity type filters stay display-only. `hiddenBy()` gives the reason a field is off the canvas - the field, the Fields switch or its type filter - and `nodeVisible()` hides the field's proxies with it. `keepHiddenFields()` moves each hidden field with its entity through a layout run, so it reappears beside the entity. The table's go-to button calls `focusField()` and stays `aria-disabled` with the reason as its title while `hiddenBy()` finds one.
- **Mode frame:** `src/mode-frame.js` (pure, no DOM) holds the frame's defaults and `frameSettings()`, which completes saved settings and drops any colour that isn't a 6- or 8-digit hex. `src/render.js` keeps them under `frame` in the `nexusSettings` entry, clears them with **Reset to defaults** and sets `--frame-view`, `--frame-edit` and `has-frame` on `#stage-root` in `applyFrame()`. `applyMode()` in `src/builder.js` sets `data-mode` there, and `src/styles.css` picks the border colour of the `#mode-frame` element in the canvas from both. The frame takes no pointer events and sits under the floating panels; exports draw only the graph, so it never appears in them.
- **Inspector breadcrumb:** `src/inspector-trail.js` (pure, no DOM) works out the entity a selection belongs to with `selectionEntity()`, which Tidy also reads, and derives the Inspector's breadcrumb from it: a field, a new field opened from an entity and the bulk fields form sit under their entity's form, and every other screen has no breadcrumb. `nodeLookup()` reads the graph's nodes for both. `Breadcrumb` in `src/inspector.js` draws it above the form and opens the entity through the builder's `select()`. The trail is re-derived on every render, so it follows relabels, undo and redo.
- **Canvas selection:** in Edit mode the canvas keeps selected the node the Inspector shows, or the entity of a new field or bulk fields form, and draws the `+` handles around it when it is an entity. `followInspector()` in `src/builder.js` subscribes to the store, moves the handles and runs `syncSelection()` 1 tick after each change of the Inspector's selection, after Cytoscape has applied its own tap selection. A tap on a node keeps a selection extended with a modifier key. Every other change leaves only the inspected node selected: the breadcrumb, the entity form's field list, a proxy tap, a rename and a new node. A tap on the empty canvas or an edge, `refreshSelection()` after undo and redo, and `updateInteraction()` sync the selection too.
- **UI (browser only):** `src/render.js` draws the model with Cytoscape, `src/builder.js` adds build-mode editing, `src/inspector.js` and `src/ui.js` are Preact components over Shoelace controls, `src/store.js` is the shared UI store and keeps raised panels in a fixed band of z-indexes, `src/export.js` handles every download (PNG, SVG, CSV and the saved document), `src/dom.js` holds the `$()` element lookup, `src/icons.js` holds inline SVG icons and `src/styles.css` styles the page.
- **Toolbar sections:** the toolbar's tools row holds 6 `.toolbar__section`s in a fixed order: New, Import, Open, Save and Export; Undo and Redo; View and Edit; Find entity; Layout and Tidy; Entities, Table, Legend and History. Each section but the last ends in a separator, drawn by its `::after` in padding reserved at the section's end, so the row wraps only between sections, no line starts with a separator, and a section that wraps in a narrow window never gives its separator a line of its own. `initToolbarSeparators()` in `src/app.js` adds `is-line-end` to the section that ends each wrapped line, and `src/styles.css` hides that section's separator but keeps the padding, so the line break can't move. A `ResizeObserver` on the row and on each section runs it, because a label change such as `Export PNG` can move a line break without resizing the row.
- **Display switches:** **Fields**, **Proxies** and **Machine names** are `sl-switch` controls at the left end of the status bar, across from the zoom controls. `render.js` reads each one's `checked` in its `sl-change` handler rather than on `click`, because a click on a switch's label clicks its input too, and sets `checked` itself when a layout or the Proxies switch turns Fields on, which fires no `sl-change`. Below `40rem` the status bar hides its hint and tips and wraps the zoom controls onto a second line, so neither group leaves the window. The switches, the tips and the zoom controls fill a window of common width, so a hovered control's description in `#statusbar-hint` hides `.statusbar__tips` while it shows.
- **Entity type settings:** `SettingsBody` in `src/ui.js` draws each entity type, and the form that adds one, as a `.type-row` grid of 4 columns: the label (or the 2 name inputs), the color picker, the symbol select and the `-` or `+` button, which only custom types and the form have. The symbol select shows the picked shape in its `prefix` slot and hides its text, and its wider list opens under the select's right edge when it would cross the window's edge. Below `17rem` the panel body gets `is-narrow` from a `ResizeObserver` and each label goes on a line above its controls. A container query can't do this, because an `inline-size` container becomes the containing block of the hoisted Shoelace popups inside it.
- **Export button:** a Shoelace split button in the toolbar. `src/app.js` fills its menu from `EXPORT_FORMATS`, and choosing a format exports it and makes the main button repeat it; until then the main button opens the menu. `loadExportFormat()` and `saveExportFormat()` in `src/export-formats.js` keep the choice in `localStorage` and ignore a stored id that names no format. The toolbar has no `z-index`, so it forms no stacking context: the hoisted menu keeps Shoelace's own `z-index` and draws over the floating panels, while a panel's select list that opens upward still draws over the toolbar.
- **Keyboard shortcuts:** each control names its shortcut in a `data-shortcut` attribute, such as `Mod+S`, `Shift+1` or `?`, and the `src/shortcuts.js` docblock describes that syntax. `src/shortcuts.js` (pure, no DOM) parses a shortcut, matches it against key presses, labels it for a Mac or another platform and places the badges of the shortcut view. `src/keyboard.js` runs every shortcut from 1 capture-phase keydown listener by clicking its control, or focusing it when it's a text field, and leaves the keys a focused text field, select or menu needs alone. It keeps the browser's zoom keys (`Mod+Plus`, `Mod+=`, `Mod+-`, `Mod+_` and `Mod+0`) from the page on every screen, and the Reset, Zoom out and Zoom in controls list them as shortcuts, so they zoom the diagram. `initPageZoomGuard()` in `src/app.js` drops a pinch outside the canvas, which reaches the page as a Ctrl+wheel event or, in Safari, as gesture events; Cytoscape zooms the diagram on a pinch over the canvas. F1 draws the shortcut view in `#shortcut-hints`, a badge per control on screen, each with its control's id in `data-for`. `src/undo.js` builds the Undo and Redo titles from the same labels, and `src/app.js` numbers the template rows 1 to 9. The inspector's new entity and new field forms take the focus when they open, so typing a name doesn't run shortcuts; a form the history remounts keeps its selection and leaves the focus alone.
- **Logo and favicon:** `logo.svg` is the README logo and `assets/favicon.svg` the browser tab icon; both turn the mark's ink white under a dark colour scheme on their own. The page draws the same mark inline as the `nexus` icon in `src/icons.js`, coloured from `src/styles.css`, because Safari renders an `<img>` SVG in the system colour scheme rather than the app's theme.
- **Version:** `src/version.js` ships as `dev`; the release workflow stamps the release tag into the deployed copy.
- **Vendored libraries:** `assets/vendor/` holds third-party builds. Don't edit, lint or format them.
- **Templates:** `src/templates.js` lists the content-model templates the landing offers - Drupal CMS and CivicTheme - with each one's label, version, summary, mark, bundle counts and upstream sources. Each ships as a saved diagram, `templates/<id>.nexus.json`, with no layout. `src/app.js` draws a row per template, and `loadTemplate()` fetches the diagram and opens it through `showDocument()`, the same path a saved file takes. `scripts/update-templates.mjs` rebuilds the diagrams from the pinned tags: it clones the sources into a temporary folder, merges them in install order so the first copy of a file wins, parses the files `isModelConfig()` in `src/parser.js` accepts and serializes the model with `documentFromGraph()` on a headless graph. Its helpers live in `scripts/lib/template-sources.mjs`. No upstream config is committed.

## Commands

```bash
# Serve the app at http://127.0.0.1:8000 (ES modules don't load over file://)
npm start

# Copy the files that ship (index.html, src/, assets/, templates/) into _site/
npm run assemble

# Run all linters (ESLint, Prettier)
npm run lint

# Auto-fix code style issues
npm run lint-fix

# Run all tests (unit, then end-to-end)
npm run test

# Unit tests only (Node's built-in test runner)
npm run test-unit

# End-to-end tests only (Playwright)
npm run test-e2e

# Unit tests with coverage (reports in .logs/)
npm run test-coverage

# Rebuild every template diagram, or 1 of them, from its pinned sources
npm run update-templates
npm run update-templates -- civictheme
```

## Testing Patterns

- `tests/unit/*.test.js` use `node:test` and `node:assert` against the pure model modules, with shared fixtures in `tests/fixtures/`.
- `tests/unit/assemble.test.js` runs `npm run assemble` and checks that `_site/` holds every file `index.html` and the templates load, so a file the app needs can't be left out of a deploy.
- `tests/unit/templates.test.js` checks every template against its saved diagram: `templates/` holds exactly 1 diagram per template, each is titled by the template's label and version and holds no layout or type settings, and `documentToModel()` draws exactly the bundles the template advertises.
- `tests/unit/template-sources.test.js` covers the update script's helpers: reading and merging the config folders in `tests/fixtures/template-sources/` with the first copy of a file winning, and building a diagram from `tests/fixtures/config-min.js` that opens as the model `parseConfig()` draws, then counting its bundles. The helpers import the vendored `assets/vendor/cytoscape.min.js`, which sets `globalThis.cytoscape`.
- `tests/unit/release.test.js` checks that every constant `release.yml` stamps is one its source module exports.
- `tests/unit/logo.test.js` checks that the `nexus` icon in `src/icons.js` draws the same shapes as `logo.svg`, that `logo.svg` turns its ink white in a dark colour scheme, and that the README shows it.
- `tests/unit/entity-types.test.js` checks the built-in entity types, and that the edit palette in `index.html` offers a button for each of them, in order, with an empty `.palette__symbol` that `paintPaletteSymbols()` in `src/builder.js` fills with `symbolSvg()`.
- `tests/unit/diagram-defaults.test.js` checks the new diagram settings and reads stored copies with `readDiagramDefaults()`: each valid value is kept, and a missing, unknown, wrongly typed or inherited value falls back to its default.
- `tests/unit/export-formats.test.js` checks the export formats and runs `loadExportFormat()` and `saveExportFormat()` against fake windows: a stored id that names no format loads nothing, and a storage that throws on access, read or write breaks nothing.
- `tests/unit/annotations.test.js` applies overlays to a small model. It also checks that the README's Annotation overlay table lists every key `src/annotations.js` reads, found by matching `data.`, `node.`, `edge.` and `field.` in its source, so a key the module starts reading fails the test until the README documents it. The README section must also name each overlay file name and annotation kind, and the landing note's `annotations.yml` must link to that section's anchor in a new tab.
- `tests/unit/icons.test.js` checks the icon lookup and that every `data-icon` in `index.html` names an icon `src/icons.js` draws.
- `tests/unit/shortcuts.test.js` parses, matches and labels shortcuts against fake key events, checks which shortcuts a focused text field, select or menu lets through, and places badges in a fake viewport. It also reads every `data-shortcut` in `index.html`: each parses, each control with one has an id, no 2 controls on the same screen share a key, and the landing screen leaves the digits to the templates.
- `tests/unit/document.test.js` imports the vendored `assets/vendor/cytoscape.min.js`, which sets `globalThis.cytoscape`, and saves headless graphs with `documentFromGraph()`. A headless graph needs `layout: { name: 'preset' }` to keep the positions it's given, and `styleEnabled: true` for `visible()` to honour `display: none`. A styled graph also needs `cy.destroy()` once the test is done, or the test process never exits. Its full document holds every key of the saved format and must survive a save unchanged, so a format change updates that document and the schema in the `src/document.js` docblock together. Only a field whose `hidden` is `true` opens hidden.
- `tests/unit/references.test.js` syncs headless graphs built from a `ContentModel` with `syncReferenceElements()`: the elements and data each reference gets, removal when a reference goes, copied label and cardinality edits, renamed proxies kept in place, and a graph already in sync left untouched.
- `tests/unit/bulk-fields.test.js` parses field lines against a fixed context of taken names, existing fields and entity ids. It covers each way of naming a field, each option column, the defaults a reused machine name gives, every error and the line numbers. It also writes definitions with `formatFieldLine()` and parses them back unchanged.
- `tests/unit/mode-frame.test.js` checks the frame defaults and completes saved settings: missing values, a non-boolean switch, and colours that aren't a 6- or 8-digit hex, including one carrying CSS.
- `tests/unit/label-fit.test.js` measures text with a fake function (10 units a character) and checks that `wrapLabel()` wraps the way Cytoscape does, that a fixed-end shape draws in a square box as Cytoscape draws it and keeps its ends the same size in a wider box, the edges `shapeSpan()` finds at a height, and that `fitWidth()` widens a box until every line on `labelX()` clears its shape by the inset and its box by the padding, with 1 of the 2 exact. A fixed-end box grows by exactly the width its text gains. `wrapLabel()` mirrors the wrapping in the vendored Cytoscape build, so a Cytoscape upgrade means checking it again.
- `tests/unit/history.test.js` edits headless graphs the way the builder, the inspector and the Fields table do. It checks snapshots, changes and their composition, that either side of a change restores the graph and its reference elements exactly, and the `History` rules: undo and redo, dropping undone steps, coalescing and what ends it, rebasing, the step limit and jumps between any 2 versions of a session. Cytoscape keeps the objects it's given, so it also checks that editing a restored graph leaves the stored versions alone.
- `tests/unit/inspector-trail.test.js` derives the breadcrumb and the entity of every selection kind from a fake node lookup, including a field, proxy or form whose entity is gone.
- `tests/unit/packing.test.js` checks `packColumns()` on small boxes: the arrangement takes the frame's shape, keeps the boxes in order, gives a tall box a column of its own, sizes each column by its widest box and spaces boxes by the gap. It checks that `tidyColumns()` leaves columns `packColumns()` arranged as they are, and how it groups boxes into columns from where they are. It checks that `keepOrder()` leaves boxes already in key order alone, even when their extents overlap, puts others in key order from the first box's start and keeps them at least the gap apart. It checks that `clearSpot()` picks the shortest shift that keeps the gap from every other box, prefers left, then up, on a tie, stays inside the frame and leaves the box where it is when no shift clears it.
- `tests/unit/store.test.js` raises panels through the store's actions and checks that the raised panel lands on top and that raised panels never leave 1 band of z-indexes, however often they're raised. It also docks panels with `dockPanel()` and checks each rail's order from `dockedPanels()`: moves within a rail and across rails, an index past the end, a closed panel keeping its place, the height a move keeps or clears, and the order an exported layout carries back. It checks that `setPanelHeight()` keeps a height between the 90px minimum and the maximum it's given. Node has no `window`, so the store starts from its default layout.
- `tests/e2e/app.spec.js` drives the app with Playwright against `tests/server.mjs`, a dependency-free static server on port 8000, with config fixtures in `tests/e2e/fixtures/`. Code inside `page.evaluate()` runs in the browser, not in Node. A Shoelace dropdown reopened while its close animation runs stays open but hidden, so `exportFrom()` waits for the Export menu to close before it returns. `locator.focus()` leaves a Shoelace button unfocused, so a keyboard test calls the button's own `focus()` through `evaluate()`. The shortcut labels follow `navigator.platform`, so a test that checks them sets the platform with `onPlatform()`, which overrides it through `page.addInitScript()` and reloads. The toolbar separator tests check each separator against the measured boxes of the sections rather than a fixed line break, because the row wraps in other places under CI's fonts than under a Mac's. A Playwright CSS locator matches inside shadow roots too, so `#settings sl-button` also counts the buttons inside each `sl-color-picker`; a test counts the settings' own buttons by their `data-` attributes.
- Coverage counts only the modules the unit tests load (`"all": false` in `.c8rc.json`), so browser-only modules don't count against the CI threshold.

## Coding Conventions

- ES modules with single quotes and 2-space indentation; Prettier formats with `printWidth: 160`.
- `camelCase` for variables, functions and properties.
- All files must end with a newline character.

## CI/CD

- `.github/workflows/test-nodejs.yml` - lint, unit tests with coverage on Node 22 and 24, a Playwright end-to-end job, and a Netlify deploy that runs once both pass: each pull request to its own preview, `main` to the project's main URL. The deploy reads the `NETLIFY_SITE_ID` variable and the `NETLIFY_AUTH_TOKEN` secret and is skipped without them. A new push to a pull request cancels its superseded run, while runs for `main` queue so they deploy in order
- `.github/workflows/release.yml` - on a published release, assembles `index.html`, `src/`, `assets/` and `templates/` into `_site` with `npm run assemble`, stamps the version and deploys to GitHub Pages at https://nexus.drevops.com
- `.github/workflows/draft-release-notes.yml` - keeps a draft release up to date as pull requests merge
- `.github/workflows/assign-author.yml` - assigns each pull request to its author
- `renovate.json` - Renovate keeps npm packages and the SHA-pinned actions up to date

## Updating from the template

This project was generated from a template and can pull the template's latest infrastructure (CI workflows, linting and test configuration, Docker, and docs) at any time. When you are asked to "update scaffold", fetch the updater skill from the template repository into the local `.claude/skills/` directory, then invoke it:

1. Create the target directory if it does not exist:

   ```bash
   mkdir -p .claude/skills/update-consumer-scaffold
   ```

2. Download the skill:

   ```bash
   curl -sSL https://raw.githubusercontent.com/AlexSkrypnyk/scaffold/main/.scaffold/skills/update-consumer-scaffold/SKILL.md -o .claude/skills/update-consumer-scaffold/SKILL.md
   ```

3. Invoke the `update-consumer-scaffold` skill and follow its steps.

The skill directory is fetched on demand and is git-ignored - it is not committed to the project.
