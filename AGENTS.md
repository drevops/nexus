# AGENTS.md

This file provides guidance to AI agents when working with code in this repository.

## Project Overview

Nexus is a static web app that draws a Drupal site's content model from its exported configuration, entirely in the browser. There's no backend and no build step: `index.html` loads the app's own ES modules and stylesheet from `src/` plus vendored libraries from `assets/vendor/`, and GitHub Pages serves the files as they are at https://nexus.drevops.com.

The project was created from the Scaffold template, which supplies the CI workflows, the linting and test tooling, and the Renovate configuration.

## Application Architecture

- **Entry point:** `index.html` declares an import map for Preact, Preact hooks and htm, loads the classic vendor scripts (Cytoscape, Dagre, cytoscape-dagre, cytoscape-svg, js-yaml) and the Shoelace autoloader, then starts `src/app.js`. The vendor scripts carry `defer`, so they don't hold up parsing and the Shoelace autoloader draws the landing card while they download; deferred and module scripts run in document order, so `src/app.js` still runs after them. The landing ships `inert` with `aria-busy="true"` and a loader in `#template-list`: `wireLanding()` replaces the loader with the template rows and `enableLanding()` clears both attributes once startup has wired every control. An inline script in `<head>` applies the stored or system theme before the first paint, and `initTheme()` reads the class back, so the landing never draws in the wrong theme while the vendor scripts load.
- **Landing screen:** the card's header puts the `nexus` mark in `.landing__mark`, beside the `h1`, the version badge and the tagline, or above them on a card narrower than `30rem`, and the note on config folders and `annotations.yml` sits inside `#dropzone`. Once the card is wide enough for 2 columns, `src/styles.css` caps `#template-list` at `80dvh` minus `--landing-chrome`, the card's height without the list, so the card stays within 80% of the window and the list scrolls past it, but never below `--landing-list-min`. In a taller window the list shows every template, and the dropzone grows to the height of the template column. A change to the header, the column headings or the card's padding means measuring `--landing-chrome` again. In 1 column the list has no cap.
- **Model builder (pure, no DOM):** `src/parser.js` turns parsed config YAML into a `ContentModel` from `src/model.js`; `src/base-fields.js` adds curated system fields and `src/annotations.js` applies the optional `annotations.yml` overlay. A reference with no target bundles points at an `Any <type>` placeholder, while a negated Paragraphs selection (`negate: 1`) targets every bundle of its type the config defines except the listed ones.
- **Shared definitions (pure):** `src/entity-types.js` lists the built-in entity types in diagram order, each with its label, default color, default symbol and the base name of bundles created on the canvas, and `formatCount()` and `pluralLabel()` word a count of each type's bundles and their plural name. `src/annotations.js` lists the annotation kinds and the file names an overlay can have, `src/save-formats.js` lists the entries of the Save menu, alphabetical by label and each submenu too, each with its label, icon and title, and `SAVE_FORMATS` lists every format they save, `src/names.js` converts between machine names, labels and file names, and `src/model.js` holds the default title, the field types the builder offers, the reference field types, the highest limited cardinality and the graph id helpers. Import them from there instead of keeping a local copy, so the copies can't drift apart.
- **Documents:** `src/document.js` converts between the live graph and a saved `.nexus.json` document. `schema/nexus.schema.json` defines the saved format as a JSON Schema (draft 2020-12) and ships with the site, at the URL its `$id` names. `documentToModel()` stays more lenient than the schema, which sets `additionalProperties: false` on every object but `ui`.
- **Markdown export:** **Save as > Markdown** builds the saved document with `currentDocument()` in `src/app.js` and writes it with `documentMarkdown()` from `src/markdown.js` (pure). `documentOutline()` in `src/document-outline.js` (pure) groups the document's entities by type, in `ENTITY_TYPE_ORDER`, then custom types, then other types by name, and sorts each group by label. `src/mermaid.js` (pure) draws the outline as a Mermaid flowchart. The contents link to GitHub's heading anchors, so `headingSlugger()` takes every heading's anchor in document order before anything is written. Text goes through `markdownText()`, which escapes `|` so a label fits a table cell, and machine names through `markdownCode()`. The Settings panel's **Markdown export** section sets `diagram` under the `markdown` key of `nexusSettings`: `auto`, the default, adds the diagram up to `MARKDOWN_DIAGRAM_LIMIT` entities.
- **HTML export:** **Save as > HTML** writes the same sections as the Markdown export as a standalone page, with `documentHtml()` from `src/html-report.js` (pure). It shares the outline, `outlineAnchors()` from `src/markdown.js`, so each heading has the anchor it has in the Markdown, and `noteParagraphs()` from `src/document-outline.js`. Every piece of document text goes through `htmlText()`. `anchorId()` gives a heading with an empty anchor an id with a `.`, which `headingSlug()` never produces. The page carries its own `<style>` and a Content Security Policy `<meta>` of `default-src 'none'; style-src 'unsafe-inline'`, so it loads nothing and runs no script, and it has no diagram.
- **CSV exports:** the 3 CSVs of the Save as menu's **CSV** submenu all go through `csvText()` in `src/csv.js` (pure), which quotes a cell holding a quote, comma or line break and joins rows with CRLF. Document text is untrusted, so `csvText()` puts a `'` before a cell that starts with `=`, `+`, `-`, `@`, a tab or a carriage return, unless the cell is a number, and a spreadsheet shows it as text. **Fields** writes the Fields table's records with `fieldsCsv()` from `src/fields-csv.js`. **Bundles** and **References** write the saved document from `currentDocument()` with `bundlesCsv()` and `referencesCsv()`, in `documentOutline()` order, so they include fields hidden on the canvas and bundles a type filter hides. The bundles CSV leaves base fields out of its field count and writes no row for an `Any <type>` placeholder. The references CSV writes 1 row per target bundle, with `*` for a field that targets every bundle of its type.
- **CSV import:** `src/fields-csv.js` (pure) holds `CSV_COLUMNS`, the columns of the fields CSV. `fieldsCsv()` writes **Save as > CSV > Fields**, `csvTemplate()` writes the template **Open > CSV template** downloads, and `csvDocument()` reads a CSV into a saved document. Its module docblock and the README's **Import a CSV** section describe the format. `parseCsv()` in `src/csv.js` reads RFC 4180 CSV, `csvSeparator()` picks the `,`, `;` or tab the header row uses most, and `cellText()` drops the `'` that `csvText()` puts before a formula, so an exported cell imports as written. `findEntityTypeByName()` in `src/entity-types.js` reads an entity type cell written as a machine name, a label or a bundle noun such as `Paragraph type`. A reference cell holds `Label (entity id)`, a custom type whose label doesn't name it is written `Label (type)`, `;` and `\` inside a list item are escaped with `\`, and `fieldsCsv()` writes a row for each entity with no fields from the controller's `entities()`, so an exported CSV imports as the same entities, fields and references. `parseCsv()` throws on a quoted cell with no closing quote, and `csvDocument()` reports it at the row the cell starts on. The template must import with no errors or warnings. `importCsv()` in `src/app.js` runs from **Open > CSV file…** and a `.csv` dropped on the dropzone, which the landing screen leaves unmentioned to stay small, opens the document through `showDocument()`, the path a saved file takes, and shows the rows' problems in the landing alert with `csvErrorLines()`. `fieldMachineName()` and `fieldLabel()` in `src/names.js` derive a field's machine name and label for the import and the bulk fields form alike.
- **Documents from AI agents:** `skills/create-nexus-diagram/SKILL.md` is an Agent Skills skill that tells an AI agent how to write a `.nexus.json` document from a screenshot, spreadsheet, spec or any other source. Its tables of entity types, builder field types, field kinds and base fields mirror `src/entity-types.js`, `src/model.js` and `src/base-fields.js`, and its JSON code block is a complete example document. `checkDiagram()` in `scripts/lib/diagram-check.mjs` runs the schema through Ajv and then the rules a schema can't express. Errors are duplicate entities, duplicate fields in an entity and annotation ids that reuse another id. Warnings are target bundles without a target type, annotation edges to unknown ids and entity types that are neither built in nor in `customTypes`. Once no entity or field repeats, it runs `checkModel()` too and reports each problem at the path of its entity or field. `scripts/check-diagram.mjs` is its CLI. The site serves the skill at the path it has in the repository, and the root `llms.txt` links the skill and the schema for an agent given only the site's address.
- **Create with AI:** the `#ai-dialog` dialog opens from **Create with AI** on the landing screen and **Create with AI…** in the Open menu, both through `showAiDialog()`, and hands the skill to an agent in 3 tabs: a prompt that links the skill, the whole skill and a `curl` command that installs it. `src/agent-skill.js` (pure, no DOM) builds the prompt and the command from the skill's URL, resolved against the page, so a preview links its own copy, and reads a pasted reply with `pastedDocument()`, taking the first fenced code block when there is one. `src/ai-dialog.js` fetches the skill when the dialog first opens, and again on the next open after a failed fetch. Its copy buttons select the text when the clipboard refuses it. **Open diagram** passes the parsed document to `showDocument()` in `src/app.js`, the path a saved file takes, and an error keeps the dialog open with the reason in `#ai-error`.
- **Links:** **Copy link** in the Save menu, after a divider below the save formats, builds the document with `currentDocument()` in `src/app.js`, drops `ui` so the receiver keeps their own panels and adds the entity of `tidyTarget()` as `focus`. `src/doc-link.js` (pure, no DOM) compresses the document's JSON with `CompressionStream('deflate')`, whose Adler-32 checksum rejects a link altered in transit, encodes it as base64url and builds `#doc=<data>&focus=<entity id>` on the page's URL with `documentLink()`. `linkParams()` reads a fragment, and `decodeDocument()` inflates it, stops past `MAX_DOCUMENT_BYTES` and turns every failure into 1 readable error. `src/link-dialog.js` shows the link in `#link-dialog` and copies it, selects it when the clipboard refuses it, and offers **Save .nexus.json** instead for a link longer than `MAX_LINK_LENGTH`. The dialog's `#link-protection` and `#link-limits` links open the README's **Link protection** and **Link limits** sections, which document the checksum, the checks on a link's content and the size limits, so a change to any of them updates that README section too. `openLink()` in `src/app.js` runs on start and on `hashchange`, opens the document through `showDocument()`, the path a saved file takes, focuses the entity when `focus` names one, and shows the alert a failed file shows. The fragment stays in the address bar, so a reload reopens the link.
- **Reference elements:** `src/references.js` derives the render-only elements that draw each reference - a proxy beside the field, the proxy edge joining them and the overview's collapsed edge - from the ref edges of a live graph. `syncReferenceElements()` reconciles them with the graph and keeps a renamed reference's proxy in place. `render.js` runs it at render time and through the controller's `syncReferences()`, which `builder.js` and `inspector.js` call after each edit the elements depend on.
- **Node text:** a Cytoscape label takes 1 style, so `src/render.js` draws each entity's type and each node's machine name in an HTML caption layer: the type on a blank last line reserved inside the entity box, the machine name below the node. `src/label-fit.js` (pure, no DOM) wraps a label the way Cytoscape does and works out how wide a box must be for every line to stay inside its shape, and where the label sits in it. `SHAPE_OUTLINES` holds the outline of each shape with corners off its bounding box. The diamond and pentagon scale with the box, while the tag, hexagon, octagon and rhomboid keep the ends they have in a square box at the same size in a wider one. Cytoscape stretches its own outline of those 4 with the width, so `render.js` draws them as a `polygon` from `polygonPoints()`. `fitWidth()` finds the narrowest box whose shape leaves every line its inset and padding, so text can run into a tag's point, and `labelX()` centres the label in the room left. A pentagon's label sits on its centroid, below the box centre, from `labelDrop()`. A proxy wraps its name over several lines like its entity, at `PROXY_BOX.textMaxWidth`, and is fitted into its shape the same way. `render.js` works each entity's and proxy's box out once in `nodeBox()`, moves the label with `text-margin-x` and `text-margin-y`, and places the type caption from the same margins, so the 2 move together. Each node's `bounds-expansion` covers its machine name, so layouts, Fit and proxy placement leave room for it. `drawWithoutLayers()` turns off Cytoscape's layered texture cache by making its `getLayers()` return `null`, because the cache copies each element's bitmap into a layer without image smoothing, which drops pixel rows from labels on a 1x display. Cytoscape then draws each element's bitmap onto the canvas itself. A Cytoscape upgrade means checking that `drawLayeredElements()` still falls back that way.
- **History:** `src/history.js` (pure) snapshots the model elements and node positions of a graph, stores each edit as the change between 2 snapshots and applies either side of a change to undo or redo it. Its `History` class holds the versions of 1 diagram, joins edits recorded with the same coalesce key and jumps to any version in 1 apply. `src/undo.js` owns the open diagram's history and wires the Undo and Redo buttons and the History panel's jumps. `builder.js`, `inspector.js`, `render.js` and `app.js` record each finished user action with `checkpoint()`, display toggles that re-run the layout go through `untracked()`, and `app.js` starts a new history for every diagram it draws.
- **Checks:** `checkModel()` in `src/model-checks.js` (pure, no DOM) reads a model in the shape of a saved document's `entities` and returns its problems as `{ level, rule, message, id }`, errors first, with `id` the graph id of the entity or field. `CHECK_RULES` lists each rule with its level and label, and the module docblock says which rules skip base fields and `*` bundles. `scripts/lib/diagram-check.mjs` runs it for `npm run check-diagram`, at the default settings. The controller's `problems()` in `src/render.js` runs it on `documentFromGraph(cy)`, and `currentProblems()` in `src/ui.js` works them out again only when the store's `version` moves, which `undo.js` bumps after every checkpoint, undo, redo and new diagram. `ChecksBody` groups them by level, and `syncChecksBadge()` puts the count on `#checks-toggle` in the colour of the worst level. A click calls the controller's `focusProblem()`, which focuses a shown field or else its entity, and in Edit mode also opens the Inspector through the builder's `select()`. A row whose entity type is hidden stays `aria-disabled`, from `canFocusProblem()`, with the reason as its title. The field limit is set in the Settings panel's **Checks** section and kept under `checks` in `nexusSettings`, read through `readCheckSettings()`.
- **Hover highlight:** `hoverNeighbourhood()` in `src/hover-highlight.js` (pure, no DOM) returns the elements a hover lights. An entity lights its fields and every reference from its fields or to it. A field lights its entity and its own references, and a proxy lights the 1 reference it draws. Each reference brings its ref edge, proxy, proxy edge, collapsed edge, field with its entity and target. `src/render.js` waits `HOVER_DELAY` after a `mouseover`, skips a pointer with a button held and then adds `hover-lit` to those elements and `hover-faded` to the rest. Both rules come last in `style()`, so they win over `faded` and the trace while the hover lasts. The focus, the search and the isolation use only `faded`, `trace` and `trace-source`, so `clearHover()` restores them by removing the 2 hover classes. A `mouseout`, a `mouseleave` of `#cy`, `tapstart`, `cxttapstart`, `boxstart`, `viewport`, `add`, `remove` and any keydown clear it, so drags, pans, box selections, edits and keyboard exports never draw it. `isFaded()` gives the captions, note badges and note bodies the opacity the hover draws. The Settings panel's **Hover highlight** switch sets `enabled` under `hover` in `nexusSettings`, read through `readHoverSettings()`. **Reset to defaults** clears it.
- **Centring in view:** Find entity, focusing an entity and focusing a field go through `centreOn()` in `src/render.js`, which centres the visible elements it's given in `openArea()`, the part of the canvas no floating panel covers. `freeArea()` in `src/free-area.js` (pure) finds the largest box of a frame that no other box overlaps, and falls back to the whole frame when that box covers less than a fifth of it. Find entity and an entity focus centre each entity together with its fields.
- **Layouts:** the toolbar's layout button is a split button like the Open and Save buttons. `render.js` fills its menu from `LAYOUTS` and re-runs the picked layout when the main button is pressed. The pick lasts for the open diagram only: `buildController()` starts each diagram from the new diagram settings, which `src/diagram-defaults.js` (pure) defines and reads back from the `newDiagrams` key of the `nexusSettings` localStorage entry. They set the layout, the detail level, the Proxies and Machine names switches and the mode `app.js` passes to `attachBuilder()`, and the Settings panel's **New diagrams** section edits them through the controller's `setDiagramDefault()`. A default of Edit mode with the Entities level starts the diagram at All, since entering Edit moves there and would re-run the layout. A stored boolean `fields` reads as All or Entities while no valid `level` is stored. A saved document keeps its positions through `applyLayout()` and takes the other settings like any new diagram. A pick from the menu runs the layout through `untracked()`, like the display toggles, while the main button and Tidy each record a `checkpoint()`. LR and TB run Dagre over the whole graph. Columns, the default, runs Dagre on each island of connected elements on its own, sorts the islands by entity type order and label, and places them with `packColumns()` from `src/packing.js`, a pure module that stacks boxes in columns shaped like the canvas. The **Tidy up** button runs Dagre on each island again and lines the islands up with `tidyColumns()` from the same module, in columns taken from where they already are, and leaves the view alone. Dagre orders an entity's fields as it likes, so `keepFieldOrder()` in `render.js` moves each field, with its proxies, back into the order the fields had before the Tidy, with `keepOrder()` from the same module: top to bottom in LR and Columns, left to right in TB. When the Inspector's screen or the node focused in View mode belongs to an entity, `tidyTarget()` returns it, Tidy works on that entity, its fields and their proxies alone, and the Tidy button's title names it. `builder.js` places a node created from a form, which has no drop position, at the nearest spot in view that clears every visible node, found with `clearSpot()` from the same module.
- **Mouse buttons:** Cytoscape zooms on the wheel only while user panning is on, so `holdPanning()` in `src/builder.js` turns it off for the length of each left-button press instead, from a capture-phase `mousedown` on the canvas. `updateInteraction()` allows grabbing, selecting and box selection only in Edit mode outside Connect, so the left button selects and moves nodes there and does nothing on the canvas elsewhere. A right-drag pans in every mode: `builder.js` follows the pointer's client coordinates on Cytoscape's `cxtdrag` events, between `cxttapstart` and `cxttapend`. Cytoscape fires no `cxttap` once the pointer has passed its tap threshold, so only a right-click without a drag isolates an entity with its fields and proxies and opens the entity menu, `#entity-menu`, at the pointer. A press outside the menu, Escape, a pan, a zoom or a mode switch closes it. Grabbing a selected node makes Cytoscape drag the whole selection. While an isolation holds in Edit mode, `dragGroup()` moves the whole group when any member is dragged, following only the node under the pointer (`grabon`), and a faded node can't be grabbed. Each drag records 1 `checkpoint()` on `dragfreeon`. A double-click on a node in View mode switches to Edit mode with the node selected. The first click focuses the node and animates the view, so the double-click opens the node the first click hit, whatever the second click lands on.
- **Bulk fields:** the entity inspector's **Bulk** button opens `BulkFieldsForm` in `src/inspector.js`, a text box taking 1 field per line. `src/bulk-fields.js` (pure, no DOM) parses the lines into field definitions, or the reason a line can't be used, and its docblock describes the line format. `formatFieldLine()` writes a definition back as a line, which the form's **Copy from** select uses to fill the box from another entity. The builder's `createFields()` adds the definitions in a column beside the entity and records 1 `checkpoint()`.
- **Panels:** `src/ui.js` draws each panel with a grip handle before its title and a pin that is tilted while the panel floats and upright in the accent colour while it's docked. Dragging the header of a docked panel undocks it on the first move; dragging the grip runs `startDockDrag()`, which moves the panel within its rail or to the other one through `dockPanel()` in `src/store.js` and never undocks it. Each panel's `order` in the store places it in its rail, `dockedPanels()` lists a side's open panels in that order, and the order is saved with the rest of the layout. A floating panel dropped on a rail lands at the pointer's place among the docked panels, while the pin button keeps the order it has. `dockStyle()` keeps each docked panel at most as tall as its content: the Inspector takes its content height up to the rail's, a panel resized by its bottom edge keeps that height as a maximum, and the rest share the free space equally. `startVResize()` passes the smaller of the content and rail heights to `setPanelHeight()` as the maximum. A floating panel has a resize handle on its left, right and bottom edges and its bottom corners instead, 1 per name in `RESIZE_HANDLES`. The edge handles straddle the border, mostly outside it, so they leave the body's scrollbars free; a floating panel has no `overflow: hidden` for them, and its body rounds its own bottom corners. `startPanelResize()` anchors the panel at its top-left corner and sets its `size` through `resizePanel()` to the box `resizeBox()` in `src/panel-resize.js` (pure, no DOM) works out: the dragged edges follow the pointer, the others stay put, and the panel stays inside the canvas and at least `MIN_PANEL_SIZE`, 200px wide and 90px tall. A double-click on any handle clears the size with `resetPanelSize()`, so the panel takes its content's size again. The size is saved with the layout, `storedSize()` drops a stored size that isn't 2 positive numbers, and a docked panel ignores it.
- **Fields table:** `src/field-table.js` (pure, no DOM) numbers each field by its place in its entity with `numberFields()`, which the `#` column shows, and `sortFields()` sorts the fields within each entity's group. Blank cells come last in either direction, and equal values keep the `#` order. Each sortable header in `src/ui.js` holds a button that sets the store's `tableSort` to `nextSort()`: ascending, then descending, then back to the `#` order. The arrow is drawn in the header cell's right padding, so it takes no column width. The entity filter, the search and the sort live in the store, so they survive the panel moving between a rail and the canvas. The panel body scrolls the table both ways, with the toolbar sticky on the left and the header row on top. Each row starts with the go-to and show buttons, then `#`, the label and the machine name in a column of its own; the 2 button columns don't sort. Column widths come from a `field-table__col--<column>` class on each header cell, and each cell carries `data-column` with its column. The CSV keeps the diagram order.
- **Editing in the Fields table:** in either mode the table edits a field's label, machine name, type, cardinality, required flag, references, help text, default value, allowed values and translatability in place. `cellEditor()` in `src/field-table.js` says which control each cell opens, or null: a system or calculated field keeps its cardinality badge, references edit only on reference field types and allowed values only on `list_*` types or fields that have some. Each editable cell draws a plain button with `data-edit-cell="<id>|<column>"`, so a large diagram costs no more to draw, and a click swaps in 1 editor from `src/table-editors.js`: `TextEditor` saves on Enter or when the focus leaves and cancels on Escape, with Shift+Enter starting a new line in help text and allowed values, and `SelectEditor` opens its list on mount, closes on `sl-hide` once the `sl-change` of a pick has run, and widens its list with `alignWideList()`. The references list takes several picks, and `referenceChanges()` turns them into `createReference()` and `removeReference()` calls. Required is a checkbox in the cell. `TextEditor` keeps its text as state, because Preact sets the `value` property on every render and raising the panel re-renders the table. The store's `editMode`, which `applyMode()` in `src/builder.js` sets, shows the settings columns in Edit mode even when no field has a setting, and a mode switch closes the open editor. Every edit goes through `src/field-edits.js`, the edits the Inspector makes too: each writes the node, records 1 `checkpoint()` and does nothing for an unchanged value, and only an edit made with `typing`, as the Inspector's inputs are, coalesces with the edit before it, so each table edit is its own step. A table edit to the field the Inspector shows, or to its entity, calls `revise()` so the form remounts with the new value. `renameField()` in the builder returns the new id and moves the Inspector only when it showed the field, and the table returns the focus to the cell under its new id after a keyboard close.
- **Shared fields:** `fieldSharing()` in `src/shared-fields.js` (pure, no DOM) groups field records by entity type and machine name, the key of a Drupal field storage. The controller's `records()` puts each record's bundles in `usedIn`, sorted by entity label. Base and calculated fields get an empty list. The Fields table's **Used in** column and the CSV show the count, and the cell's title, from `usedInTitle()`, names the bundles. The field Inspector's **Also used in** section, `SharedWith` in `src/inspector.js`, lists the other bundles with each one's label for the field and opens a bundle through the builder's `select()`. Everything reads the live graph on each render, so edits, undo and redo update the counts.
- **Descriptions and field settings:** `src/parser.js` reads each bundle's `description` and each field's help text (`description`), `default_value`, storage `allowed_values` and `translatable` into the model, and `ContentModel.toArray()` puts each in the node data only when it has a value, through `fieldSettingsData()` in `src/model.js`. `documentFromGraph()` saves them the same way, so a missing key and an unknown translatability stay apart from an empty value and `false`. `src/field-settings.js` (pure, no DOM) holds `settingText()`, which counts blank text as missing, and reads, writes and labels allowed values, which the Inspector edits as 1 `value|label` line each. The entity and field Inspector forms edit them through `TextSetting` and `TranslatableSetting` in `src/inspector.js`, which call `setSetting()` and `setFieldTranslatable()` from `src/field-edits.js`; those remove a cleared key and record 1 `checkpoint()` per edit. `translatableChoice()` and `translatableValue()` in `src/field-settings.js` convert between a translatability and the `yes`/`no` choice of its select, for the Inspector and the table alike. `typeOptions()` and `cardinalityOptions()` in `src/model.js` list the types and cardinalities a field can take, with a field's own type or cardinality added when the builder's lists lack it. Help text and bundle descriptions are HTML in Drupal, so the tooltip and the Fields table draw their markup through `parseRichText()` in `src/rich-text.js` (pure). It keeps only the tags in `RICH_TEXT_TAGS`, with no attribute but a link's `href`, drops every other tag but keeps its text, drops `script`, `style` and the rest of `DROPPED_CONTENT` with their content, and decodes entities into plain text. The table draws the tree as Preact elements with `richText()` in `src/ui.js`, and the tooltip as HTML from `richTextHtml()`, which escapes every string. A link draws as `span.rich-text__link` titled with its address, so nothing in a document can navigate the page. The Inspector edits the text as written, and the CSV, the Markdown export and the HTML report keep it as written. In View mode the table draws its Help text, Default, Allowed values and Translatable columns only while a field of the diagram has a setting, and in Edit mode always; with them it takes a minimum width that the panel body scrolls sideways. The CSV always has the 4 columns.
- **Notes:** a Note is an annotation node of kind `NOTE_KIND` (`note`), placed from the palette's **Note** button, whose `note` holds Markdown. `parseNoteMarkdown()` in `src/note-markdown.js` (pure) reads headings, paragraphs, line breaks, bold, italics, `__underline__`, strikethrough, code spans and links into the tree of `src/rich-text.js`, so `richTextHtml()` escapes every string and draws a link as a non-navigating span. It caps nesting at `MAX_NESTING` and a link label at `MAX_LINK_LABEL`, so long runs of openers stay linear. `render.js` draws each Note's body in the `#note-bodies` layer: `noteSize()` measures the body at zoom 1 in a probe, cached by text, and sets the Cytoscape box, and `positionNoteBodies()` scales the body with the zoom over the box. `rebuildNotes()` and `positionNotes()` cover the bodies and the badges together, and a Note gets no badge and no tooltip. Exports leave HTML layers out, so `withNoteLabels()` in `src/export.js` shows each Note's plain-text label, from `noteMarkdownPlain()`, while `cy.png()` or `cy.svg()` runs. The Inspector's `NoteForm` edits the text and the annotation kind selects leave `note` out.
- **Explore view:** **Explore from here** in the entity menu and the entity Inspector calls the builder's `explore()`, which clears an isolation and starts the controller's explore view. `exploreEntities()` in `src/explore.js` (pure) walks the reference links between entities, outward, inward or both, up to a depth of 1 to 5, and `readExplore()` completes a `{ depth, direction }` choice. The walk follows every ref edge, including those of hidden fields and filtered types. `exploreOutside()` in `src/render.js` keeps the ids of the entities outside the view and of the annotations attached to nothing inside it, so a field follows its entity, a proxy its target, and a node created during the view shows. Starting saves every node position, the viewport and the display switches, and `clearExplore()` puts them back, or runs the layout again when a switch changed. Every layout run and the restore go through `untracked()`, so the view records no history step. `goToVersion()` in `src/undo.js` clears the view before an undo, redo or jump, `deleteNode()` clears it when its entity goes, `syncReferences()` carries it over renames, and `currentDocument()` in `src/app.js` saves through `withoutExplore()`, so a document, link or export keeps the diagram's own layout. PNG, SVG, Mermaid and DOT draw what is shown. Every layout of the view also clears the hover highlight. `src/explore-bar.js` draws `#explore-bar` in the status bar in place of the tips: the entity, the depth select, the direction radio group and **Clear**. The status bar wraps while the bar shows, so it stays inside a narrow window. Opening the entity menu and every layout of the view hide the canvas tooltip, because Cytoscape fires no `mouseout` when the node leaves the pointer. The last depth and direction carry over to the next view in the session.
- **Hidden fields:** the Fields table's eye button calls the controller's `setFieldHidden()` in `src/render.js`, which sets `hidden: true` on the field node or removes the key, and records a `checkpoint()`. The key is model data, so the history and the saved document carry it, while the entity type filters stay display-only. `hiddenBy()` gives the reason a field is off the canvas - the field, the detail level, its type filter or the explore view - and `nodeVisible()` hides the field's proxies with it. `keepHiddenFields()` moves each hidden field with its entity through a layout run, so it reappears beside the entity. The table's go-to button calls `focusField()` and stays `aria-disabled` with the reason as its title while `hiddenBy()` finds one.
- **Mode frame:** `src/mode-frame.js` (pure, no DOM) holds the frame's defaults and `frameSettings()`, which completes saved settings and drops any colour that isn't a 6- or 8-digit hex. `src/render.js` keeps them under `frame` in the `nexusSettings` entry, clears them with **Reset to defaults** and sets `--frame-view`, `--frame-edit` and `has-frame` on `#stage-root` in `applyFrame()`. `applyMode()` in `src/builder.js` sets `data-mode` there, and `src/styles.css` picks the border colour of the `#mode-frame` element in the canvas from both. The frame takes no pointer events and sits under the floating panels; exports draw only the graph, so it never appears in them.
- **Connection lines:** the toolbar's **Lines** dropdown, after **Tidy up**, picks the line style of every diagram. `src/connection-lines.js` (pure, no DOM) lists the styles in `LINE_OPTIONS`, each with its label, title, menu icon and the Cytoscape edge style that draws it, and `readLineSettings()` completes saved settings. Right-angled, the default, draws `taxi` edges with a `taxi-turn` of `50%`, which Cytoscape measures across the gap to each target, so lines from 1 node to targets of different widths turn at points a few pixels apart. Merged sets the turn to `MERGED_TURN` pixels, which Cytoscape measures from the source node's edge, so every line leaving a node on 1 side turns at the same point and the lines share 1 trunk. Cytoscape draws an L-shaped line instead when the gap to the target is shorter than the turn plus `taxi-turn-min-distance`, so `MERGED_TURN` stays well below the gap between layout ranks. Straight draws `bezier` edges, which run straight between 2 nodes and bow apart only edges that share both ends, where Cytoscape's `straight` style would draw them on top of each other. `src/render.js` fills `#lines-menu` from `LINE_OPTIONS`, spreads `lineStyle()` into the `edge` rule of `style()`, keeps the setting under `lines` in the `nexusSettings` entry, and reapplies the stylesheet and relabels the button in the controller's `setLines()`. The style is a display preference, so the saved document, a link, the history and **Reset to defaults** leave it alone, while PNG and SVG exports draw it.
- **Inspector breadcrumb:** `src/inspector-trail.js` (pure, no DOM) works out the entity a selection belongs to with `selectionEntity()`, which Tidy also reads, and derives the Inspector's breadcrumb from it: a field, a new field opened from an entity and the bulk fields form sit under their entity's form, and every other screen has no breadcrumb. `nodeLookup()` reads the graph's nodes for both. `Breadcrumb` in `src/inspector.js` draws it above the form and opens the entity through the builder's `select()`. The trail is re-derived on every render, so it follows relabels, undo and redo.
- **Canvas selection:** in Edit mode the canvas keeps selected the node the Inspector shows, or the entity of a new field or bulk fields form, and draws the `+` handles around it when it is an entity. `followInspector()` in `src/builder.js` subscribes to the store, moves the handles and runs `syncSelection()` 1 tick after each change of the Inspector's selection, after Cytoscape has applied its own tap selection. A tap on a node keeps a selection extended with a modifier key. Every other change leaves only the inspected node selected: the breadcrumb, the entity form's field list, a proxy tap, a rename and a new node. A tap on the empty canvas or an edge, `refreshSelection()` after undo and redo, and `updateInteraction()` sync the selection too. A box selection that leaves the inspected node out closes the Inspector on `boxend`, and a sync with no node inspected leaves the selection as it is, so the boxed nodes stay selected.
- **UI (browser only):** `src/render.js` draws the model with Cytoscape, `src/builder.js` adds build-mode editing, `src/inspector.js` and `src/ui.js` are Preact components over Shoelace controls, `src/store.js` is the shared UI store and keeps raised panels in a fixed band of z-indexes, `src/export.js` handles every download (PNG, SVG, the 3 CSVs, the CSV template, Markdown, HTML, Mermaid, DOT and the saved document), `src/dom.js` holds the `$()` element lookup, `src/icons.js` holds inline SVG icons and `src/styles.css` styles the page.
- **Hover titles:** every control, table header and badge carries a `title`, and `untitledControls()` in `tests/e2e/titles.spec.js` fails on any that doesn't, on each screen, panel, Inspector form and menu. Shoelace's button, input, textarea, switch and checkbox copy a `title` property to an inner element only, so `initUI()` installs `titleShoelaceHosts()` from `src/host-titles.js`, a Preact `options.vnode` hook that sets the `title` of every `sl-*` element as an attribute on the host instead.
- **Toolbar sections:** the toolbar's tools row holds 6 `.toolbar__section`s in a fixed order: New, Open and Save; Undo and Redo; View and Edit; Find entity; Layout, Tidy up and Lines; Entities, Fields, Legend, History and Checks. Each panel toggle's label is the title of the panel it opens. Each section but the last ends in a separator, drawn by its `::after` in padding reserved at the section's end, so the row wraps only between sections, no line starts with a separator, and a section that wraps in a narrow window never gives its separator a line of its own. `initToolbarSeparators()` in `src/app.js` adds `is-line-end` to the section that ends each wrapped line, and `src/styles.css` hides that section's separator but keeps the padding, so the line break can't move. A `ResizeObserver` on the row and on each section runs it, because a label change such as `Layout: LR` can move a line break without resizing the row.
- **Detail levels:** the status bar's level split button picks which fields the canvas shows. `src/detail-levels.js` (pure, no DOM) lists the levels in `DETAIL_LEVELS`, each with its label and title, in the order `F` cycles them: Entities shows no field and draws the collapsed edges, References the non-base fields of a `REFERENCE_FIELD_TYPES` type, Configurable every field but base fields, so calculated fields too, and All every field. `levelShowsField()` decides a field from its `kind` and `fieldType`, and `levelHidesTitle()` words the go-to button's title for a field the level hides, naming the first level that shows it. `#detail-level` moves to `nextLevel()` and `Alt+F` opens `#detail-menu` from its caret. The controller's `setDetailLevel()` re-runs the layout through `untracked()`, so the level records no history step, and the saved document doesn't carry it. Proxies follow their field, so turning Proxies on at Entities moves to References, and entering Edit mode at Entities moves to All. `refresh()` covers only the fields present when it runs, so `render.js` re-applies the level to a field on its `add` and `data` events, and a new, renamed or retyped field follows it. A field the user creates or retypes is never left off the canvas: `selectCreated()` and `createFields()` in `src/builder.js` and `setFieldType()` in `src/field-edits.js` call the controller's `revealFields()`, which moves to `levelToShow()`, the first level that shows those fields, after the edit's `checkpoint()`. `#detail-level::part(label)` keeps `20ch`, the length of `Fields: Configurable`, so cycling the levels leaves the switches beside it in place.
- **Display switches:** **Proxies** and **Machine names** are `sl-switch` controls at the left end of the status bar after the level button, across from the zoom controls. `render.js` reads each one's `checked` in its `sl-change` handler rather than on `click`, because a click on a switch's label clicks its input too. Below `47rem` the status bar hides its hint and tips, wraps the zoom controls onto a second line and lets the display controls wrap among themselves, so no group leaves the window. The display controls, the tips and the zoom controls fill a window of common width, so a hovered control's description in `#statusbar-hint` hides `.statusbar__tips` while it shows.
- **Entity type settings:** `SettingsBody` in `src/ui.js` draws each entity type, and the form that adds one, as a `.type-row` grid of 4 columns: the label (or the 2 name inputs), the color picker, the symbol select and the `-` or `+` button, which only custom types and the form have. The symbol select shows the picked shape in its `prefix` slot and hides its text, and its wider list opens under the select's right edge when it would cross the window's edge. Below `17rem` the panel body gets `is-narrow` from a `ResizeObserver` and each label goes on a line above its controls. A container query can't do this, because an `inline-size` container becomes the containing block of the hoisted Shoelace popups inside it.
- **Open and Save buttons:** Shoelace split buttons in the toolbar. The main Open button opens the saved diagram picker, and its menu's items, `OPENERS` in `src/app.js`, open the picker, return to the landing screen through `showLanding()`, open the CSV picker `#csv-open`, download the CSV template or open the Create with AI dialog. The main Save button always saves the `.nexus.json` document. `src/app.js` fills the Save as menu from `SAVE_MENU`, before **Copy link**, with an entry that has `formats` as a submenu, and choosing a format saves in that format once, through `SAVERS`. A click on a submenu's own item, such as its icon, selects that item, so the `sl-select` listener stops it before the dropdown closes. The menu items carry no shortcuts, because a shortcut runs only a control on screen; each caret has one. The toolbar has no `z-index`, so it forms no stacking context: the hoisted menu keeps Shoelace's own `z-index` and draws over the floating panels, while a panel's select list that opens upward still draws over the toolbar.
- **Text exports:** the Mermaid and Graphviz DOT formats of the Save as menu draw the graph the canvas shows, from `src/diagram-text.js` (pure, no DOM). The controller's `canvasGraph()` in `render.js` passes `canvasGraph()` every element without the `hidden` class, with each node's position and drawn size, the layout's direction, each type's color, symbol and label, and the Machine names switch. So the detail level, the Proxies and Machine names switches, the type filters and hidden fields shape the text as they shape the canvas. `canvasGraph()` keeps entity, field, proxy and annotation nodes and has, ref, proxy, collapsed and annotation edges, in canvas order. A Note's text is `noteMarkdownPlain()` of its Markdown, 1 line per block, drawn in its yellow box. `identifiers()` turns each node id into an ASCII identifier, gives ids that clash a `_2`, `_3` suffix and prefixes Mermaid keywords such as `end`. `toMermaid()` writes a `flowchart` with Mermaid 11.3's `@{ shape: ... }` syntax: `MERMAID_SHAPES` maps each symbol to the nearest shape Mermaid has, fields are stadiums, `classDef` lines carry the canvas's fills, borders and dashes, and `linkStyle` lines the edge colours. Mermaid lays the flowchart out itself. It encodes `#`, `\`, `"`, backticks, markup, braces and `|` as Mermaid's `#` codes and writes the title as a JSON string in the front matter, which Mermaid reads before it decodes codes. A flowchart past Mermaid's 50,000-character limit goes through `MERMAID_COMPACTIONS` in turn until it fits: short `n1`, `n2` ids without indentation, the classic shape syntax where it draws the same shape, then no machine names, then no type captions. `mermaidCompactionNote()` writes a `%%` note naming every change but the classic shapes. `toMermaid()` takes the limit as an optional third argument, so tests drive each step on a small graph. Past `MERMAID_MAX_ENTITIES` entities, `MERMAID_MAX_EDGES` edges or a text still over the limit, the file also starts with a note to use DOT. `toDot()` keeps the canvas layout: `layout=neato` with `inputscale=72` pins each node at its canvas position in points, with `y` negated, at least as large as the canvas draws it. `DOT_SHAPES` maps each symbol to a Graphviz shape. A node with a type caption or machine name gets an HTML-like label so those lines can be smaller and muted. Quoted labels escape `&` too, because Graphviz decodes entities there.
- **Keyboard shortcuts:** each control names its shortcut in a `data-shortcut` attribute, such as `Mod+S`, `Shift+1` or `?`, and the `src/shortcuts.js` docblock describes that syntax. `src/shortcuts.js` (pure, no DOM) parses a shortcut, matches it against key presses, labels it for a Mac or another platform and places the badges of the shortcut view. `src/keyboard.js` runs every shortcut from 1 capture-phase keydown listener by clicking its control, or focusing it when it's a text field, and leaves the keys a focused text field, select or menu needs alone. It keeps the browser's zoom keys (`Mod+Plus`, `Mod+=`, `Mod+-`, `Mod+_` and `Mod+0`) from the page on every screen, and the Reset, Zoom out and Zoom in controls list them as shortcuts, so they zoom the diagram. `initPageZoomGuard()` in `src/app.js` drops a pinch outside the canvas, which reaches the page as a Ctrl+wheel event or, in Safari, as gesture events; Cytoscape zooms the diagram on a pinch over the canvas. F1 draws the shortcut view in `#shortcut-hints`, a badge per control on screen, each with its control's id in `data-for`. `src/undo.js` builds the Undo and Redo titles from the same labels, and `src/app.js` numbers the template rows 1 to 9. The inspector's new entity and new field forms take the focus when they open, so typing a name doesn't run shortcuts; a form the history remounts keeps its selection and leaves the focus alone.
- **Logo and favicon:** `logo.svg` is the README logo and `assets/favicon.svg` the browser tab icon; both turn the mark's ink white under a dark colour scheme on their own. The page draws the same mark inline as the `nexus` icon in `src/icons.js`, coloured from `src/styles.css`, because Safari renders an `<img>` SVG in the system colour scheme rather than the app's theme.
- **Version:** `src/version.js` ships as `dev`; the release workflow stamps the release tag into the deployed copy.
- **Vendored libraries:** `assets/vendor/` holds third-party builds. Don't edit, lint or format them. Each is a published npm build, byte for byte, and `vendor.json` records its package, version, path in the package and SHA-256 digest; a folder's digest is the SHA-256 of its `sha256sum` listing. `scripts/lib/vendor.mjs` reads the record and compares files, and `scripts/check-vendor.mjs` downloads each package with `npm pack` into `.artifacts/tmp/` and compares the vendored files with it.
- **Untrusted input:** opened documents, links, imported config, pasted replies and stored settings are data. `src/type-styles.js` (pure) holds `SYMBOLS` and the checks on entity type styles: `typeColors()`, `typeSymbols()` and `customTypeList()` keep only machine-name types with hex colours, known symbols and string labels, because `symbolSvg()` writes colours and symbols into markup that goes into `innerHTML`. `render.js` runs every colour, symbol and custom type through them, and any other text that reaches `innerHTML` goes through `esc()`, or through `richTextHtml()` when its markup is drawn. `index.html` sets a Content Security Policy `<meta>` before any script: scripts and requests from the page's own origin, `data:` requests for Shoelace's system icons and a `sha256-` hash for each inline script, so editing an inline script means updating its hash. `.npmrc` sets `ignore-scripts=true`.
- **Templates:** `src/templates.js` lists the content-model templates the landing offers - Drupal CMS, CivicTheme, Umami, Thunder and Open Social - with each one's label, version, summary, mark, bundle counts and upstream sources. Each ships as a saved diagram, `templates/<id>.nexus.json`, with no layout. `src/app.js` draws a row per template, and `loadTemplate()` fetches the diagram and opens it through `showDocument()`, the same path a saved file takes. `scripts/update-templates.mjs` rebuilds the diagrams from the pinned tags: it clones the sources into a temporary folder, merges them in install order so the first copy of a file wins, parses the files `isModelConfig()` in `src/parser.js` accepts and serializes the model with `documentFromGraph()` on a headless graph. It writes the rebuilt diagram's bundle counts into `src/templates.js`, counting only the built-in entity types, since an entity of another type is only a reference target. With `--latest` it first moves each source to its highest stable `X.Y.Z` or `vX.Y.Z` tag, never an older one, and writes the tags and the version into `src/templates.js` too; `--pr <dir>` writes a pull request `title.txt` and `body.md`, and `--list` prints the template ids as JSON and builds nothing. Nothing in the scripts or the workflow names a template, so adding one takes only its entry in `TEMPLATES`, with `id` first, 1 source named after its `label` and 1 `ref` line per source. Its helpers live in `scripts/lib/template-sources.mjs`, and `scripts/lib/template-versions.mjs` (pure) reads `git ls-remote` tags, rewrites 1 template's lines in `src/templates.js` at any indentation and words the pull request. No upstream config is committed.

## Commands

```bash
# Serve the app at http://127.0.0.1:8000 (ES modules don't load over file://)
npm start

# Copy the files that ship (index.html, llms.txt, src/, assets/, templates/, schema/, skills/) into _site/
npm run assemble

# Run all linters (ESLint, Prettier)
npm run lint

# Auto-fix code style issues
npm run lint-fix

# Run all tests (unit, then end-to-end)
npm run test

# Unit tests only (Node's built-in test runner)
npm run test-unit

# End-to-end tests only (Playwright)
npm run test-e2e

# Unit tests with coverage (reports in .logs/)
npm run test-coverage

# Rebuild every template diagram, or 1 of them, from its pinned sources
npm run update-templates
npm run update-templates -- civictheme

# Move a template to its latest upstream tags and rebuild it
npm run update-templates -- --latest civictheme

# Check diagram documents against the schema and the rules it can't express
npm run check-diagram -- path/to/diagram.nexus.json

# Check the vendored libraries against their npm packages (needs the registry)
npm run check-vendor
```

## Testing Patterns

- `tests/unit/*.test.js` use `node:test` and `node:assert` against the pure model modules, with shared fixtures in `tests/fixtures/`.
- `tests/unit/assemble.test.js` runs `npm run assemble` and checks that `_site/` holds every file `index.html` and the templates load, the document schema, the skill and an `llms.txt` that links both, so a file the app or an agent needs can't be left out of a deploy.

## CI/CD

- `.github/workflows/test-nodejs.yml` - `Lint`, `Unit` (unit tests with coverage), `E2E 1` and `E2E 2` (Playwright, each running the spec files tagged with its `@runner-N`), and a Netlify deploy that runs once all of them pass: each pull request to its own preview, `main` to the project's main URL. The deploy reads the `NETLIFY_SITE_ID` variable and the `NETLIFY_AUTH_TOKEN` secret and is skipped without them. A new push to a pull request cancels its superseded run, while runs for `main` queue so they deploy in order. Every job runs on the Node version in the workflow's `NODE_VERSION`, the latest LTS release. The job names carry no version, so a Node upgrade leaves the required checks of the `main` ruleset (`Lint`, `Unit`, `E2E 1` and `E2E 2`) alone. The runner tags split the spec files alternately by name, not by duration
- `.github/workflows/release.yml` - on a pushed version tag, in 3 jobs: `Build` checks the tag is a version on a commit in `main`, assembles `index.html`, `llms.txt`, `src/`, `assets/`, `templates/`, `schema/` and `skills/` into `_site` with `npm run assemble`, stamps the version, packs `nexus-<tag>.tar.gz` and `checksums.txt`, attests their provenance and copies the bundle to `nexus-<tag>.intoto.jsonl`, the file OpenSSF Scorecard looks for on a release; `Publish` attaches them to the draft release with that tag and publishes it, and only warns when the release was already published by hand; `Deploy` deploys to GitHub Pages at https://nexus.drevops.com, in a `pages` concurrency group on that job only, so a waiting deploy gives way to a newer one but every tag still publishes its release. Releases are immutable and a tag ruleset limits tags to maintainers and admins
- `.github/workflows/audit.yml` - OpenSSF Scorecard on `main` only, publishing its results, and CodeQL over the JavaScript and the workflows on pull requests and `main`, skipping `assets/vendor/`. On a pull request Scorecard runs only its local checks, which upload 1 of the 3 code scanning categories `main` has, so code scanning would report every pull request as neutral with "2 configurations not found"
- Every workflow sets `permissions: {}` and grants permissions per job. The `Unit` job also runs `npm run check-vendor`
- `.github/workflows/draft-release-notes.yml` - keeps a draft release up to date as pull requests merge
- `.github/workflows/assign-author.yml` - assigns each pull request to its author
- `.github/workflows/update-templates.yml` - daily, or on demand for every template or the 1 its `template` input names, builds its matrix from `update-templates.mjs --list` and runs `npm run update-templates -- --latest` once per template and opens or force-updates its pull request on an `update-templates/<id>` branch with `peter-evans/create-pull-request`, which deletes the branch when nothing is left to change. Pushes made with `GITHUB_TOKEN` start no `pull_request` workflows, so it dispatches `Test Node.js` on the branch whenever the pull request's head commit has no run of it yet, and the checks land on that commit
- `renovate.json` - Renovate keeps npm packages and the SHA-pinned actions up to date

## Updating from the template

This project was generated from a template and can pull the template's latest infrastructure (CI workflows, linting and test configuration, Docker, and docs) at any time. When you are asked to "update scaffold", fetch the updater skill from the template repository into the local `.claude/skills/` directory, then invoke it:

1. Create the target directory if it does not exist:

   ```bash
   mkdir -p .claude/skills/update-consumer-scaffold
   ```

2. Download the skill:

   ```bash
   curl -sSL https://raw.githubusercontent.com/AlexSkrypnyk/scaffold/main/.scaffold/skills/update-consumer-scaffold/SKILL.md -o .claude/skills/update-consumer-scaffold/SKILL.md
   ```

3. Invoke the `update-consumer-scaffold` skill and follow its steps.

The skill directory is fetched on demand and is git-ignored - it is not committed to the project.
